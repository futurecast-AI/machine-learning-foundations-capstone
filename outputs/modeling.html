Hourly bike-rental prediction with a random forest¶

Author: AI Foundations (Edward Hickman)

Task: supervised learning — regression. Estimate recorded hourly rental counts from calendar information and contemporaneously observed weather, not an advance forecast using unavailable future weather. This uses real 2011–2012 Capital Bikeshare data from the UCI Bike Sharing dataset (Fanaee-T, 2013; Fanaee-T & Gama, 2014). MODELING_PLAN.md records the fixed evaluation choices before training.

2. Separate development and later test dates¶

Reserve the last 20% of unique dates (rounded up) for the final test. Entire dates stay together. Do not use test outcomes for model choices, plots of target distributions during development, or preprocessing fits. This prevents learning from the future relative to the evaluated period, a leakage concern discussed by Kapoor and Narayanan (2023).

3. Preprocessing and fixed models¶

The eight categorical predictors are one-hot encoded so their numeric codes are not treated as ordered measurements. Unknown categories at prediction time are ignored rather than learned from validation/test data. Four provider-normalized numeric weather features pass through unchanged. There are no missing values to impute; extra feature scaling is unnecessary for these tree thresholds.

Exclude casual and registered: their sum reveals cnt exactly. Also exclude the row identifier and raw date. These exclusions and training-only preprocessing implement leakage precautions (Kapoor & Narayanan, 2023). Random forests combine trees and can represent nonlinear interactions (Breiman, 2001); a depth cap and minimum leaf size limit complexity, without guaranteeing absence of overfitting.

In [4]:
preprocessor = ColumnTransformer([
    ("categorical", OneHotEncoder(handle_unknown="ignore", sparse_output=False),
     CATEGORICAL),
    ("numeric", "passthrough", NUMERIC)], remainder="drop")
forest_parameters = dict(n_estimators=150, max_depth=14, min_samples_leaf=2,
                         max_features=1.0, bootstrap=True,
                         criterion="squared_error", random_state=SEED, n_jobs=1)
models = {
    "Training-mean baseline": Pipeline([
        ("preprocess", clone(preprocessor)),
        ("model", DummyRegressor(strategy="mean"))]),
    "Random forest": Pipeline([
        ("preprocess", clone(preprocessor)),
        ("model", RandomForestRegressor(**forest_parameters))])
}

def regression_metrics(actual, predicted):
    """Return rental-count error metrics and the evaluation-set R-squared."""
    return {"mae": float(mean_absolute_error(actual, predicted)),
            "rmse": float(root_mean_squared_error(actual, predicted)),
            "r2": float(r2_score(actual, predicted))}

4. Development-only expanding-window validation¶

Three expanding folds operate on unique development dates, with one whole calendar day omitted between each training and validation period. Fit a new encoder and estimator inside each fold. This fixed-model diagnostic is not hyperparameter tuning or an independent-samples confidence interval. Different seasons and changing use can produce different errors even without changing the model.

RMSE is primary, emphasizing large rental-count misses. MAE reports the mean absolute miss in rentals per recorded hour. These losses express different priorities, not interchangeable definitions of accuracy (Hodson, 2022). R² compares squared error with using the evaluation period's actual mean and can be negative; it is not percent accuracy (scikit-learn developers, n.d.).

5. Final fitting and held-out evaluation¶

Keep the pre-specified model unchanged. Fit on all development rows, then compute predictions for the final later-date test once in this run. Report the baseline even if it outperforms the forest. Retain training scores to make the generalization gap visible; temporal shift means the gap is not solely a measure of overfitting.

In [6]:
fitted_models = {}
results = []
predictions = test[["instant", "timestamp", "hr", "workingday"]].copy()
predictions["actual"] = y_test.to_numpy()
for name, template in models.items():
    estimator = clone(template).fit(X_dev, y_dev)
    fitted_models[name] = estimator
    train_predictions = estimator.predict(X_dev)
    test_predictions = estimator.predict(X_test)
    for partition, actual, predicted in [
        ("development_training", y_dev, train_predictions),
        ("held_out_test", y_test, test_predictions)]:
        results.append({"model": name, "partition": partition,
                        "n": len(actual), **regression_metrics(actual, predicted)})
    column = "forest_prediction" if name == "Random forest" else "baseline_prediction"
    predictions[column] = test_predictions
metrics = pd.DataFrame(results)

7. Limitations and responsible use¶

These historical records cover one system, two years and only observed hours; there is no evidence that unrecorded hours had zero rentals. Observed rentals also omit demand that could not be served. Current weather in this evaluation is not a weather forecast, so these scores do not demonstrate advance deployment performance. The forest cannot reliably extrapolate outside training patterns, and temporal dependence or changing use can undermine future accuracy. Neither the average score nor time-of-day errors establish fairness across neighborhoods or demographic groups; the necessary data are absent. Before operational use, validate on later data with genuinely available inputs and audit station/service coverage rather than automatically withdrawing bikes from historically low-use areas.

8. Notebook summary¶

I modeled recorded hourly bike rentals as a supervised regression problem using calendar and contemporaneously observed weather inputs. I trained a fixed 150-tree random forest and compared it with a training-mean baseline using chronological development folds and later test dates. On 3,488 held-out records, the forest achieved RMSE 104.65 and MAE 72.57 rentals per recorded hour, with R² 0.775, versus baseline RMSE 232.56. Important challenges were target-leaking rental subtotals, temporal shift, unrecorded hours, and the difference between observed weather and forecast inputs. The results support only this historical conditional-prediction evaluation, not causal conclusions, demographic fairness or production readiness.
